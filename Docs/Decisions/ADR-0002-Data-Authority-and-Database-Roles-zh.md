# ADR-0002：数据权威、Git 策略与数据库角色

**状态：** 已接受
**日期：** 2026-08-30
**决策者：** 项目所有者
**相关问题：** OQ-003、OQ-006、OQ-014

> Agent 使用的英文主文档：
> [`ADR-0002-Data-Authority-and-Database-Roles.md`](ADR-0002-Data-Authority-and-Database-Roles.md)。

## 背景

当前个人项目使用可迁移的 Markdown 和 JSON 文件，并用 Git 保存持久研读内容及用户数据的历史。目标平台还需要书籍目录、平台管理的元数据、检索、任务状态，以及未来可能不同的注释和讨论持久层。

如果不按实体划分权威，“数据库是 Source of Truth”这个表述会过于宽泛。同一个数据库可以同时包含权威记录和完全可重建的投影。

## 决议

### 按实体声明权威

每个 Schema 或数据表必须声明为以下一种角色：

- **权威数据：** 该记录是持久 Source of Truth，必须有备份、迁移、导出和冲突规则；
- **派生数据：** 该记录可以从声明的权威输入重建；
- **运行数据：** 该记录用于协调本地任务或缓存，并有明确恢复策略。

不能仅仅因为一项记录存进数据库，就把整个存储引擎中的数据一概视为权威。

### 当前个人阶段

- 保存的原件、审核 Markdown、参考资料、当前书籍元数据、注释和讨论继续以文件为权威来源。
- 在项目所有者的个人环境中，这些持久文件可以由 Git 管理。
- 临时文件、生成 HTML、缓存、处理投影和检索索引继续排除在外或保持可重建。

本 ADR 不会立即迁移当前的 `Metadata/book.yml`、注释或讨论。

### 目标 SQLite 角色

平台现在可以引入新的本地 SQLite 数据库，用于：

- 权威的平台 Book Catalog；
- 在完成明确且有测试的迁移之后，保存权威的平台管理书籍 Metadata；
- 保存导入、构建和迁移任务的运行状态；
- 保存派生的全文检索、Context 检索和目录投影。

即使搜索和检索记录与权威目录或元数据位于同一个 SQLite 数据库，它们仍然是**派生数据**。它们的事实来源是审核后的正文与声明的参考输入，并且必须可以重建。

书籍 Metadata 转为 SQLite 权威数据时，平台必须提供文档化的导出方式或可迁移书籍包表示。在该迁移得到实施和验证之前，当前文件 Metadata 仍然是权威来源。

### 用户数据持久化

个人阶段的注释与讨论继续以带 Schema 版本的 JSON 文件为权威来源。内部版或外部版未来可以把它们迁入能够保留 JSON 文档语义、修订、导出和可迁移性的数据库。具体引擎与迁移契约继续由 OQ-016 决定。

“原生支持 JSON”是后续评估条件，不是本 ADR 已经选定的数据库。

### 知识图谱持久化

OQ-014 决定：已接受知识使用稳定 ID、人类可读 Markdown、别名和证据链接。图谱与搜索存储默认是派生投影。Graph 数据库可以作为投影层候选，但引擎选择与实际必要性继续由 OQ-017 决定。

## 后果

- SQLite 可以同时包含权威、派生和运行数据表；每个 Schema 必须标记自己的角色。
- 权威数据表需要备份和迁移；派生数据表需要重建测试。
- 检索索引损坏或删除不能毁掉书籍内容。
- 提取平台期间，当前文件型阅读器继续有效。
- 未来用户数据数据库必须支持无损导出和经过测试的迁移；仅仅便于保存 JSON 还不够。
- 没有新决议时，Graph 数据库不能静默取代人类可读的已接受知识。

## 未选方案

- 把一个数据库中的每一项记录都宣布为权威。
- 在内部版或外部版持久化需求明确之前，立即迁移当前笔记和讨论。
- 把检索或图谱索引作为书籍正文或已接受知识的唯一副本。

## 迁移与验证

- 创建平台数据表之前，先发布 Schema 和角色标签。
- 测试权威数据库的备份、导出、Schema 迁移和恢复。
- 测试搜索、检索和图谱投影的确定性重建。
- 把 Metadata 权威从文件切换到 SQLite 前执行双读对比，避免长期维护双写权威。
- 在 OQ-016 得到接受并且存在向后兼容迁移之前，不修改当前用户数据文件。
