# ADR-0001：产品边界、部署方向与分发阶段

## 背景

Christian Studies 当前以浏览器应用加 loopback 本地服务的形式运行。这是发现并验证阅读、注释和 AI Context 需求的最快方式。未来可能先把项目介绍给读书会朋友；如果其他人也认为有价值，再扩大分发范围。

当前需要确定首要产品边界，但没有必要提前构建账户、云同步、协作或租户系统。

## 决议

### 产品边界

第一版平台是**本地优先、单读者的个人环境**。可信边界是用户自己的机器。身份和 API 不应彻底封死未来的多用户设计，但在新的产品决议得到接受之前，不实现云端账户、同步、租户或共同阅读。

项目所有者会先了解读书会朋友的参与意愿，再决定是否值得发展协作版或面向更多读者的版本。

### 运行方向

开发阶段继续使用当前的**浏览器加 loopback 本地服务**，因为它适合快速实现、测试和迭代核心需求。

本记录最初选择**以 Web 应用技术为基础的桌面应用**作为首个可分发产品。ADR-0004 已取代这一终端优先级：首个专用设备目标现在是能够独立运行的 iPhone App，桌面端继续作为以后可能的客户端。原生边界与打包技术仍由后续实施规范决定。

个人版中的“注册用户”是建立本地 Profile 或完成本地初始化，并不创建远程账户。API Key 在本机配置，并且必须使用平台批准的秘密存储边界。

### 分发阶段

1. **个人阶段：** 项目所有者在本机使用。持久内容、注释和讨论可以由 Git 管理；临时、生成和派生数据不进入 Git。
2. **内部阶段：** 读书会朋友可以自行部署应用。共享书籍和研读资料仍可由 Git 管理，但每位读者自己的注释和讨论只保存在本地，不上传到共享仓库。
3. **外部阶段：** 对外分发的应用不包含书籍。可以包含分发权利允许使用的圣经资源。读者通过正式导入流水线，自行导入 Markdown、Word、EPUB、PDF 或其他受支持材料。

外部版最终支持哪些格式仍取决于正式导入规范和 fixture；本 ADR 不会绕过 OQ-007，擅自扩大首发格式范围。

## 后果

- 本地优先、离线阅读和可迁移数据继续作为设计约束。
- 当前 Web 实现是可以继续演进的基础，而不是需要丢弃的原型。
- 应用 API 使用稳定身份和范围受限的资源，但不引入推测性的多用户基础设施。
- 专用设备客户端是目标，不是立即重构的要求；ADR-0004 已把移动端设为优先方向。
- Git 纳入规则取决于分发阶段和数据所有权。
- 个人数据默认不能进入内部共享仓库或外部发行包。
- 公开版或协作版需要新的决议，覆盖账户、同步、冲突、管理和分享权限。

## 未选方案

- 把托管式多用户产品作为第一版平台。
- 把当前浏览器开发方式直接视为最终打包决定。
- 仅仅为了未来可能需要，就提前实现账户或云同步。

## 迁移与验证

- 提取应用外壳时保持当前《追寻敬虔》的行为。
- 内部版或外部版发布前，定义对应阶段的默认忽略和导出策略。
- 测试内部版和外部版不会包含个人笔记、讨论、秘密或未经授权的书籍内容。
- 把打包和本地秘密存储列为任何专用设备版本的正式验收领域；ADR-0004 进一步规定 iOS Keychain 边界。
