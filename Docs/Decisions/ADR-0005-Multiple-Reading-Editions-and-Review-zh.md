# ADR-0005：多阅读版本与审核发布

**状态：** 已接受
**日期：** 2026-09-05
**决策者：** 项目所有者
**相关问题：** 《追寻敬虔》第五章试验的直接产品决策

> Agent 使用的英文主文档：
> [`ADR-0005-Multiple-Reading-Editions-and-Review.md`](ADR-0005-Multiple-Reading-Editions-and-Review.md)。

## 背景

当前书籍模型和阅读器假定 `Reading/` 下每章只有一份规范 Markdown
正文。《追寻敬虔》将试验第二个阅读版本：以收到的中文译稿为基础，
并用获准供个人使用的英文第五章校核原意，形成 ChatGPT 辅助的现代简体
润译版。

现有 Word 转写中文必须继续保留，不能被静默替换。AI 草稿不能伪装成
已经批准的作者正文。笔记和讨论包含准确文字、Offset 与来源修订，因此
不能自动移植到另一版本。

## 决议

### 版本身份与权威

每个阅读版本使用稳定的 `editionId`。第五章试验采用：

- `legacy-zh`：收到的繁体中文 Word 转写版，并继续作为默认版本；
- `chatgpt-zh-cn`：ChatGPT 辅助的现代简体中文润译版。

每个版本都是独立审核的阅读正文权威。对润译版而言，英文原文是判断
作者含义的最高依据；现有中文版本则继续是自身措辞和初始段落对应关系
的权威。润译时发现二者冲突，必须留下审核记录，不能静默掩盖。

### 目标目录与版本清单

目标可迁移目录为：

```text
Books/<Book-Slug>/
├── Reading/
│   ├── <现有部分目录>/<旧版章节>.md
│   └── chatgpt-zh-cn/<章节>.md
└── Metadata/
    ├── editions.json
    ├── Reading-Units/<editionId>/<chapterId>.json
    └── Edition-Reviews/<targetEditionId>/<chapterId>.json
```

`Metadata/editions.json` 是版本目录的权威来源，声明默认版本，以及每个
版本的身份、显示名称、语言、来源版本、出处、发布状态和各章明确路径/
状态。阅读器和服务不能通过扫描重复章号来推断权威文件。

收到的默认版本保留现有路径，避免仅为统一目录而改变相对引用、来源修订、
笔记和讨论。新的替代版本使用 `Reading/<editionId>/<章节>.md`。版本归属
由明确的 Manifest 决定，不要求物理目录完全对称。在正文发现和校验遵守
版本与发布状态之前，相同 `chapterId` 的第二份正文不得进入普通阅读器。

### 阅读单元与段落对应元数据

`Metadata/Reading-Units/<editionId>/<chapterId>.json` 是可审核的身份
Sidecar，不是正文副本。它包含：

- `schemaVersion`、`bookId`、`editionId` 和 `chapterId`；
- Markdown 路径及其内容修订；
- 按顺序排列的语义块，每块含稳定 UUID、块类型、序号和内容哈希。

`Metadata/Edition-Reviews/<targetEditionId>/<chapterId>.json` 保存润译
审核流程和跨版本对应关系，包括：

- 来源和目标版本、章节身份及修订；
- 润译规则版本和术语表版本；
- 模型身份、生成时间及参考来源定位；
- 每个对应块的稳定 `pairId`、来源块 UUID、目标块 UUID、两侧内容
  哈希、审核状态和审核时间；
- 全章发布状态和批准时间。

审核 Sidecar 不得保存完整的原中文、润译中文或英文正文。Markdown 始终
是唯一的权威正文副本。块内容哈希发生变化时，该块此前的批准自动失效。

审核者的修改要求以追加式批注保存在对应块上，每条批注为待处理或已处理。
存在待处理批注时不能批准该块或整章；润译正文改变后，该块退回草稿，但保留
已有批注。审核界面中的权威正文保持只读，使批注与正文修订始终可以区分。

审核界面可以只读、可收起地显示获许可的英文原稿作为参考。为兼容浏览器，
同源运行时代理可以从审核记录所列的固定来源网址把 PDF 读取到内存；不得把
英文 PDF 或提取后的完整英文正文持久化到仓库、审核 Sidecar 或生成的阅读器产物。

### 对齐与发布

第五章试验保持标题、块引用、脚注链接、段落顺序及语义块一一对应。
可以在同一个 Markdown 段落内拆分或合并句子；未经明确审核的对齐变更，
不得拆分、合并、新增、删除或重排 Markdown 段落。

块状态依次为 `draft` → `reviewed` → `approved`。已批准目标正文发生实质
修改后，必须撤销该块的批准。发布以整章为单位：只有全部必要块获得批准
且章节校验通过，润译章才会出现在普通阅读器中。草稿和已审核但未批准的
内容只能在审核界面中查看。

### 运行身份与 URL

所有与版本有关的运行身份均为：

```text
(bookId, editionId, chapterId)
```

笔记、讨论、修订、检索单元、上下文 Manifest 和 API 路由都必须携带
`editionId`。任何准确文字的 Offset 都不能跨版本复用。跨版本定位必须
使用经过审核的块对应关系。

普通阅读 URL 可以明确指定已批准版本；未指定时使用版本清单声明的默认
版本。请求尚未发布或不存在的版本时，应回退到默认版本并显示提示；审核
界面可以直接打开草稿或已审核内容。

## 后果

- 现有版本继续可读，不会被 AI 内容覆盖。
- 以后可以增加更多版本，而不把语言代码误当成版本身份。
- 审核过程可追溯，同时不会制造第三份正文权威。
- 启用多版本写入前，现有笔记和讨论 Schema 必须迁移。
- 在协同迁移完成前，现有扁平路径和不带版本的章节 URL 保持兼容。

## 校验与迁移门槛

发布第一个替代版本前必须：

1. 校验 `editions.json`、阅读单元 Sidecar 和审核 Sidecar；
2. 在不移动或改写文件的前提下，把当前章节路径登记为 `legacy-zh`；
3. 让构建、服务、检索、笔记、讨论和上下文 Manifest 使用复合身份；
4. 保留现有用户数据，并明确映射到 `legacy-zh`；
5. 校验一一对应的块结构及脚注链接一致性；
6. 保证未批准版本不能进入普通阅读器输出；
7. 测试显式版本 URL、默认回退、跨版本定位和修改后的批准失效。
