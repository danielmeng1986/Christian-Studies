# ADR-0003：稳定块身份与精确选区

**状态：** 已接受
**日期：** 2026-08-30
**决策者：** 项目所有者
**相关问题：** OQ-008

> Agent 使用的英文主文档：
> [`ADR-0003-Stable-Block-Anchoring.md`](ADR-0003-Stable-Block-Anchoring.md)。

## 背景

当前阅读器按照渲染块顺序生成 Block ID，并保存 Offset、准确文字、前后文和来源修订。它支持精确选区，但在前面插入新块时，后续 Block ID 可能整体变化。

逐句 UUID 能提供更细身份，但句子划分受到语言和标点影响，会显著增加身份数量，也会迫使笔记模型把句界当成编辑事实。段落或语义块身份已经可以解决主要的插入问题，同时不必放弃精确选区。

## 决议

持久锚点容器采用**经过审核的语义块**，通常是段落、标题、列表项或引用中的段落。每个块分配一个稳定且不透明的 UUID，并在构建和普通编辑之间保持不变。

注释或讨论锚点包含：

- 稳定的阅读单元 ID；
- 稳定的块 UUID；将来支持跨块锚点时可以是有顺序的块 UUID 列表；
- 选中的准确文字；
- 选中部分在规范块文本中的 Offset；
- 前后文；
- 来源修订或内容哈希；
- 锚点 Schema 版本。

笔记不必覆盖整个段落。稳定块 UUID 提供持久位置，引用和 Range Selector 则保留读者的精确选区。第一版通用 Schema 可以继续只允许单块注释；跨块支持需要明确的 Schema 扩展和测试。

第一版平台模型不要求持久句子 UUID。句子划分可以作为派生的阅读或 AI 功能。只有真实使用证明有必要，并通过新的决议，句子才能成为持久身份层。

UUID 在权威 Markdown 中的物理表示——内联属性、Sidecar 身份映射或其他可审阅机制——留给版本化 Reading Document Model 规范选择。该选择必须维持 Markdown 的权威地位，不能建立另一份单独维护的正文。

## 恢复行为

1. 解析阅读单元和稳定块 UUID。
2. 使用来源修订和准确文字验证 Offset。
3. 块发生编辑后，只在同一块中恢复唯一的准确或上下文匹配。
4. 只有明确迁移或重新定位操作才能搜索其他块。
5. 没有唯一匹配时，保留用户数据并标记为未解决，绝不绘制误导性高亮。

在相邻位置插入或移动其他块，不能改变已有块 UUID。拆分、合并、复制或实质替换块时，需要明确的身份规则，并可能触发锚点迁移。

## 后果

- 在某段之前插入新内容，不再破坏该段的持久身份。
- 不必给每个句子分配 UUID，也能继续支持精确选区。
- 导入和编辑工作流必须有意识地保存块 UUID。
- 仅有 UUID 不能替代修订验证和引用上下文。
- 在迁移当前顺序型 ID 前，Reading Document Model 必须先定义规范块文本和身份保留方式。

## 未选方案

- 把渲染顺序型 Block ID 作为长期持久身份。
- 把 DOM 路径作为持久锚点。
- 要求所有笔记只能附着在完整段落上。
- 在第一版平台中给每个句子分配持久 UUID。

## 迁移与验证

- 增加稳定 UUID 时，不直接重写用户笔记。
- 针对固定来源修订，建立当前确定性 Block ID 到稳定 UUID 的映射。
- 迁移时保留现有引用、Offset、前后文和来源哈希。
- 测试插入、删除、移动、拆分、合并、重复文字和歧义恢复。
- 保留可恢复的迁移记录，绝不能丢弃未解决锚点。
