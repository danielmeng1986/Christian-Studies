# 《追寻敬虔》本地交互式电子书 Roadmap

> 中文审核版。对应的英文执行版：`interactive-ebook-roadmap.md`。

英文版用于推进执行；阶段或里程碑的修改必须在同一次变更中同步到中文审核版。

## 1. Roadmap 原则

Roadmap 以可验收的阶段组织，不预设日期。每个阶段只有在出口条件满足后才进入下一阶段，以免界面、笔记数据和构建流程同时变化而难以定位问题。

第五章原型是第一里程碑；用户实际阅读并反馈后，才扩展到全书。

## 2. 总体里程碑

| 里程碑 | 结果 |
| --- | --- |
| M0：规范冻结 | 需求、实施规范、数据源决定一致 |
| M1：可阅读原型 | 第五章可构建、可在 localhost 阅读 |
| M2：脚注闭环 | 左栏脚注交互完整 |
| M3：笔记闭环 | 笔记可写入每章 JSON 并恢复高亮 |
| M4：第五章验收 | Safari、Chrome 均通过验收 |
| M5：实际使用修订 | 根据真实阅读体验调整规范和实现 |
| M6：全书构建 | 同一流程覆盖全部章节 |

## 3. 阶段 0：规范与项目骨架

### 工作

- 固化需求分析、实施规范和 Roadmap。
- 建立 `Web/src`、`Web/scripts`、`Web/tests` 和 `Notes/Annotations`。
- 增加 `Web/dist`、缓存、日志和临时笔记文件的 Git 忽略规则。
- 建立第五章空笔记文件 `Notes/Annotations/05.json`。
- 锁定 Markdown 解析依赖和 Python 运行方式。
- 建立统一的构建、测试和本地启动入口。

### 出口条件

- 目录职责清楚，源文件与生成物不会混淆。
- 空笔记 JSON 通过 schema 校验。
- 本地启动程序只能绑定 `127.0.0.1`。
- 需求文档、实施规范和实际目录没有冲突。

## 4. 阶段 1：确定性构建与正文阅读

### 工作

- 读取第五章 YAML 元数据和 Markdown。
- 将标题、段落、引用、斜体和普通链接转换为语义化 HTML。
- 为可批注正文块生成稳定的 `data-block-id`。
- 生成共享 CSS、JavaScript 引用和第五章页面。
- 建立三栏布局、工具栏及窄屏抽屉。
- 在工具栏预留章节导航下拉菜单；MVP 只显示第五章。
- 实现明色、暗色和护眼主题。
- 实现主题和栏位偏好的 `localStorage` 恢复。

### 出口条件

- 第五章一个 `h1`、八个 `h2` 及正文格式正确。
- 同一输入连续构建两次没有输出差异。
- `dist` 不含笔记、绝对路径和构建时间。
- Safari、Chrome 中正文宽度、滚动和三种主题可正常使用。

### 里程碑

达到 M1：可阅读原型。

## 5. 阶段 2：脚注系统

### 工作

- 解析 `Footnotes-05.md` 并建立脚注索引。
- 在构建时校验正文链接与脚注目标。
- 实现左栏脚注卡片。
- 实现单条开关、单卡关闭、全部显示和清空。
- 加入打开状态、键盘操作和辅助技术标签。
- 为以后经文内容预留左栏内容类型接口。

### 出口条件

- 第五章 35 条脚注均能显示正确内容。
- 两个译者注等非数字标识正常工作。
- 同时打开多个脚注时顺序稳定。
- 脚注操作不改变正文滚动位置。
- Safari、Chrome 行为一致。

### 里程碑

达到 M2：脚注闭环。

## 6. 阶段 3：章节 JSON 与本地保存服务

### 工作

- 实现章节笔记 JSON schema 和校验。
- 实现 `GET /api/chapters/05/notes`。
- 实现带修订号的 `PUT /api/chapters/05/notes`。
- 实现同源校验、会话写入令牌、请求大小限制和章节白名单。
- 实现临时文件加原子替换。
- 实现过期修订号冲突响应。
- 使用临时目录完成 API 和故障测试。

### 出口条件

- 空数据和已有数据均可读取。
- 合法保存会生成稳定、适合 Git diff 的 JSON。
- 非法路径和非法 schema 无法触及仓库文件。
- 模拟写入失败后，原文件保持完整。
- 两个标签页使用旧数据保存时不会静默互相覆盖。

## 7. 阶段 4：正文选择与笔记闭环

### 工作

- 将浏览器选区转换为规范正文块、偏移和上下文。
- 实现选区附近的“写笔记”按钮。
- 实现有效选区的辅助右键入口。
- 拒绝跨块、纯空白、包含脚注标记和重叠选区。
- 实现右栏新建、取消、保存、查看、修改和删除。
- 实现橙色高亮和本章笔记列表。
- 实现未保存提示、保存错误和修订冲突界面。
- 实现锚点恢复及“需要重新定位”状态。

### 出口条件

- 保存后立即更新 `Notes/Annotations/05.json`，编辑器关闭并出现高亮。
- 刷新和重启服务后能从 JSON 恢复笔记。
- 点击高亮能打开正确笔记并再次保存。
- 删除成功后 JSON 记录和高亮同时消失。
- 保存失败时用户输入不会丢失。
- 正文变化后不会把笔记高亮到错误文字。

### 里程碑

达到 M3：笔记闭环。

## 8. 阶段 5：第五章综合验收

### 自动检查

- 构建确定性和 Markdown 结构测试。
- 脚注完整性测试。
- JSON schema、原子写入和冲突测试。
- 笔记锚点、重叠判断和恢复算法测试。
- `dist` 不包含笔记内容的检查。

### Safari、Chrome 人工检查

- 三主题视觉和橙色高亮对比度。
- 三栏独立滚动与窄屏抽屉。
- 鼠标选择、拖动选择、右键和浮动按钮。
- 中文、英文、斜体附近的选择边界。
- 脚注链接附近选择和禁止规则。
- 未保存退出、保存失败和多标签冲突。
- 长笔记和大量脚注的滚动体验。

### 出口条件

- `interactive-ebook-requirements-zh.md` 第 13 节全部通过。
- `interactive-ebook-implementation-spec-zh.md` 的完成定义全部满足。
- 已知问题被记录，并明确区分“阻止使用”和“可后续改善”。

### 里程碑

达到 M4：第五章验收。

## 9. 阶段 6：真实阅读反馈与第二轮规范

第五章投入实际阅读后，重点观察：

- 左栏同时打开多少脚注最自然；
- 右栏列表和编辑器之间的切换是否顺畅；
- 单块选择限制是否经常阻碍批注；
- 橙色高亮在三主题下是否过强或过弱；
- 保存一次便产生 Git 变化是否符合预期；
- 正文继续校订时，锚点恢复成功率如何；
- 是否需要笔记搜索、排序、标签或 Markdown 格式。

反馈处理顺序：

1. 先记录实际问题和复现步骤。
2. 判断问题属于需求、交互、数据模型还是实现缺陷。
3. 先修订需求和实施规范，再修改代码。
4. 若 JSON schema 改变，必须提供迁移脚本和向后兼容测试。

### 里程碑

达到 M5：实际使用修订。

## 10. 阶段 7：扩展到全书

### 工作

- 建立全书章节清单和正文—脚注映射。
- 为每章生成对应空笔记 JSON。
- 批量构建全书页面和章节导航。
- 加入上一章、下一章和目录入口。
- 对每章执行脚注完整性和结构审计。
- 验证章节切换时笔记 API 始终访问正确 JSON。
- 保持单章构建能力，避免每次修改都必须重建全书。

### 出口条件

- 所有章节可由统一配置构建，不存在章节专用手写 HTML。
- 每章笔记只写入自己的 JSON。
- 任一章节构建失败不会生成误导性的半成品全书。
- 全书构建仍可重复，`dist` 仍不含笔记。

### 里程碑

达到 M6：全书构建。

## 11. 后续候选功能

以下内容只进入候选池，不进入第一版承诺：

- 左栏显示经文；
- 跨正文块批注；
- 重叠批注或多色高亮；
- 笔记 Markdown、标签、搜索和排序；
- 手工重新定位失配笔记；
- 全文搜索和章节目录；
- 将笔记导出为阅读札记 Markdown；
- IndexedDB 离线缓存；
- PWA 或桌面应用封装；
- 多设备同步。
- 面向多章节和更多资源的完整 REST API。

是否采用 IndexedDB，应由全书规模、离线需求或搜索性能的实际数据决定，而不是在第一版预先增加第二份持久化数据源。

## 12. 下一步

按本 Roadmap，下一项实施工作是阶段 0：建立项目骨架、第五章空笔记 JSON、确定性构建入口以及受限的本地启动入口。完成阶段 0 后，再开始正文页面视觉实现。
