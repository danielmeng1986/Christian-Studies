# 《追寻敬虔》本地交互式电子书实施规范

> 中文审核版。对应的英文执行版：`interactive-ebook-implementation-spec.md`。

英文版用于约束实施，中文版用于技术审核。技术变更必须在同一次修改中同步到两个版本；如两者冲突，应先停止实施并完成对齐。

## 1. 规范状态

本规范落实 `interactive-ebook-requirements-zh.md` 中已经确认的产品决定。第一版以第五章为目标，后续所有章节沿用同一构建与运行机制。

实施时若需要偏离本规范，应先修改规范并说明数据兼容影响，尤其不得在没有迁移方案的情况下改变笔记 JSON 结构或正文锚点规则。

## 2. 技术基线

### 2.1 应用形态

- 前端是由 HTML、CSS 和原生 JavaScript 组成的静态应用。
- Markdown 在构建阶段转换为 HTML，浏览器不负责解析源 Markdown。
- 本地服务绑定 `127.0.0.1`，同时提供静态文件和受限的笔记 API。
- 第一版不使用 React、Vue、IndexedDB、Service Worker 或云端服务。
- `localStorage` 只保存主题和栏位开关等界面偏好。
- 正式支持当前项目机器上的 Safari 和 Chrome。

### 2.2 实施语言

- 构建器和本地服务使用 Python 3。
- Markdown 解析使用一个支持 CommonMark、标题、引用、强调和链接的固定版本解析器，并将依赖记录在项目内。
- 本地服务的文件读写和 HTTP 层优先使用 Python 标准库，避免引入完整 Web 框架。
- 浏览器端使用 ES Modules 或单一原生 JavaScript 入口，不依赖 CDN。

选择 Python 是为了与本书现有 Word 转 Markdown 工具保持同一自动化环境；这不影响浏览器端仍使用标准 HTML、CSS 和 JavaScript。

## 4. 构建规范

### 4.1 构建输入

每章构建配置至少包含：

- `bookId`；
- `chapterId`；
- 正文 Markdown 的仓库相对路径；
- 对应脚注 Markdown 的仓库相对路径；
- 输出页面路径。

第五章的固定标识为：

```text
bookId: qfg
chapterId: 05
notes: Books/追寻敬虔/Notes/Annotations/05.json
page: Books/追寻敬虔/Web/dist/chapters/05/index.html
```

构建器应从 YAML 元数据读取书名、章号和来源信息，但 YAML 本身不显示在正文中。

### 4.2 Markdown 映射

第一版采用直接语义映射：

| Markdown | HTML |
| --- | --- |
| `#` | 页面唯一的 `h1` |
| `##` | `h2` |
| 普通段落 | `p` |
| `>` 引用 | `blockquote`，内部保留段落 |
| `*text*` | `em` |
| 普通链接 | `a` |
| 指向 `Footnotes-XX.md#anchor` 的链接 | 脚注触发链接 |

脚注触发链接必须带有：

```html
<a class="footnote-ref"
   href="#footnote-1"
   data-footnote-id="1"
   aria-controls="footnote-panel"
   aria-expanded="false">[1]</a>
```

构建器应验证正文中的每个脚注标识都能在脚注文件中找到。缺失脚注是构建错误，不生成看似成功的完整页面。

### 4.3 正文块标识

可批注块包括 `h1`、`h2`、普通段落和引用中的独立段落。每个块生成唯一的 `data-block-id`，例如：

```html
<p data-block-id="05-p-0017">……</p>
```

第一版块标识按解析后的正文块顺序稳定生成。笔记恢复不能只依赖这个标识，还必须使用选中文字及前后文进行校验和回退搜索。

用于计算文字偏移的“可批注文本”遵循以下规则：

- 包含普通文字和 `em` 等行内语义元素中的文字；
- 不包含脚注链接文字、按钮、隐藏模板或辅助界面文字；
- 连续选择必须完全处于同一个 `data-block-id` 内；
- 保存的偏移量以 JavaScript 字符串索引为准，并始终用 `exact` 再校验。

### 4.4 脚注编译

- 脚注 Markdown 的每个二级标题代表一条脚注。
- 数字和 `译者注1` 等文字标识均作为字符串处理。
- 每条脚注被编译为页面中的惰性模板或静态章节数据。
- 脚注正文保留段落、斜体和普通链接。
- 脚注内容可以进入 `dist`，但笔记内容不可以。

### 4.5 可重复构建

相同输入必须生成字节稳定或语义稳定的输出。构建产物中不得写入：

- 当前时间；
- 随机 ID；
- 当前用户目录的绝对路径；
- 浏览器笔记或章节笔记 JSON 内容。

构建前清理的目标只能是明确的 `Web/dist/`。构建完成后应验证脚注数量、标题数量、目录目标、资源路径和笔记内容缺失性。

## 5. 页面结构规范

页面顶层结构：

```text
应用工具栏
└── 三栏阅读区
    ├── 左栏：脚注面板
    ├── 中栏：正文 article
    └── 右栏：笔记面板
```

### 5.1 工具栏

工具栏至少包含：

- 当前章节标题；
- 已构建章节之间的章节导航；
- 本章目录控件；
- 明色、暗色、护眼色主题选择；
- 左栏开关；
- 右栏开关；
- 保存状态提示。

主题和栏位状态保存到 `localStorage`。不得把正在编辑但尚未保存的笔记正文写入 `localStorage` 并冒充已保存状态。

构建器按正文顺序从渲染后的 `h1`、`h2` 标记生成本章目录，每一项链接到该标题所使用的同一确定性正文块标识。目录以工具栏弹层打开，不占用左侧参照栏。浏览器根据中栏滚动位置更新 `aria-current="location"`、当前分节名称和阅读百分比。打开、关闭或使用目录不得改变脚注、笔记或讨论状态；按 Escape 关闭弹层并把焦点还给触发按钮。窄屏复用同一目录，只隐藏触发按钮中非必要的辅助文字。

### 5.2 三栏

- 桌面宽度充足时使用 CSS Grid 同时显示三栏。
- 中栏文字宽度以 42–48 个中文全角字符为目标。
- 左右栏固定于视口范围并独立滚动。
- 窄屏时左右栏转换为覆盖式抽屉；Safari 和 Chrome 的行为必须一致。
- 隐藏侧栏不得清除脚注状态、当前笔记或未保存的编辑内容。

### 5.3 三种主题

主题以根元素属性和 CSS 自定义属性实现：

```html
<html data-theme="light|dark|sepia">
```

所有主题必须定义页面背景、正文、次要文字、边框、链接、按钮、输入框、焦点环、脚注激活状态和笔记高亮。

高亮统一使用橙色系：

- 明色主题：浅橙底配深色文字；
- 暗色主题：较深橙褐底配浅色文字；
- 护眼主题：低饱和暖橙底配深棕文字。

高亮还应有细边线或其他非颜色提示。最终色值在浏览器实测后确定，不能降低正文可读性。

## 6. 脚注交互规范

前端维护按打开顺序排列的脚注标识列表。

- 点击未打开的脚注：加入列表、显示卡片，并把该卡片滚动到左栏可见范围。
- 点击已经打开的脚注：从列表移除，只关闭这一条。
- “显示全部”：按正文引用首次出现的顺序显示全部脚注。
- “清空”：清空列表。
- 每张卡片的关闭按钮只关闭本卡片。
- 打开状态同步到对应链接的 `aria-expanded` 和激活样式。
- 操作左栏不得改变正文滚动位置。

左栏内容对象保留 `type` 字段，第一版值为 `footnote`；以后可加入 `scripture`，但不得为尚未实现的经文功能编写假数据。

## 7. 章节笔记 JSON 规范

### 7.1 文件结构

第五章使用 `Notes/Annotations/05.json`，初始结构如下：

```json
{
  "schemaVersion": 1,
  "bookId": "qfg",
  "chapterId": "05",
  "notes": []
}
```

一条笔记结构：

```json
{
  "id": "uuid",
  "sourceRevision": "sha256-of-canonical-article-text",
  "anchor": {
    "blockId": "05-p-0017",
    "startOffset": 24,
    "endOffset": 39,
    "exact": "用户选中的原文",
    "prefix": "选区前最多三十二个字符",
    "suffix": "选区后最多三十二个字符"
  },
  "body": "纯文本笔记",
  "format": "plain-text",
  "createdAt": "2026-08-27T12:00:00.000Z",
  "updatedAt": "2026-08-27T12:00:00.000Z"
}
```

约束：

- `id` 创建后不得改变。
- `bookId`、`chapterId` 必须与请求章节一致。
- `body` 是纯文本，可以为空白以外的任意 Unicode 文本。
- `exact` 必须为非空文字。
- `startOffset < endOffset`。
- 第一版中同一章节内的有效选区不得重叠。
- 时间使用 UTC ISO 8601；编辑时只更新对应笔记的 `updatedAt`。
- 笔记数组按 `createdAt`、再按 `id` 稳定排序。
- 文件使用 UTF-8、LF、两空格缩进，并以换行结束。

### 7.2 JSON 是唯一真实数据源

- 页面加载时从 API 读取整章 JSON。
- 浏览器内存只是当前会话的工作副本。
- 创建、编辑或删除成功的定义是：服务器已经原子写入 JSON，并返回新文件修订号。
- API 保存失败时，前端不得移除“未保存”状态。
- 第一版不把笔记复制到 IndexedDB。

## 8. 本地服务与 API 规范

### 8.1 启动和绑定

- 服务只绑定 `127.0.0.1`，不得默认监听局域网地址。
- 端口可配置；默认端口固定，避免不同地址产生不同的浏览器偏好存储。
- 启动时校验仓库根目录、`Web/dist` 和笔记目录。
- 若 `dist` 不存在或已过期，启动程序应给出清晰的构建提示。
- 服务可以自动打开默认浏览器，但不能假定默认浏览器就是唯一受支持浏览器。

### 8.2 API

第一版只提供整章读取和整章保存：

```text
GET /api/chapters/05/notes
PUT /api/chapters/05/notes
```

这些是 MVP 的最小接口。路由与处理逻辑应保持可分离，以便以后演进为更完整的 REST API；第一版不得为尚未确认的资源增加推测性接口。

`GET` 返回章节 JSON，并在响应中提供代表当前文件内容的修订号或 `ETag`。

`PUT` 要求：

- `Content-Type: application/json`；
- 请求体符合笔记 schema；
- 请求携带客户端读取时得到的修订号；
- 修订号不一致时返回 `409 Conflict`，不得覆盖磁盘文件；
- 成功后返回规范化数据和新的修订号。

### 8.3 文件安全

服务器必须：

- 将章节 ID 对照构建清单，不能把 URL 参数直接拼接成文件路径；
- 只允许访问 `Notes/Annotations/` 中已登记章节的 JSON；
- 限制请求体大小；
- 拒绝非 JSON 写入；
- 检查同源请求，并使用仅本次服务会话有效的写入令牌；
- 写入同目录临时文件，刷新后通过原子替换更新目标文件；
- 写入失败时保留原文件；
- 不提供通用文件浏览、执行命令或任意路径写入接口。

### 8.4 多标签冲突

若 Safari、Chrome 或两个标签页同时打开同一章，后保存者可能基于旧数据编辑。服务使用修订号拒绝过期写入。前端收到冲突后：

1. 保留用户尚未保存的文本；
2. 提示磁盘版本已变化；
3. 提供重新加载磁盘版本的操作；
4. 第一版不自动合并两个版本。

## 9. 笔记交互与锚点恢复

### 9.1 创建

1. 监听正文中的文字选择，不处理侧栏选择。
2. 把浏览器 Range 映射为同一正文块内的规范文字偏移。
3. 排除纯空白、跨块、包含脚注标记或与现有笔记重叠的范围。
4. 在选区附近显示“写笔记”按钮。
5. 点击按钮后在右栏显示引用原文和纯文本编辑框。
6. 用户点击保存后才生成 UUID、时间字段并调用 API。
7. API 成功后关闭编辑器并绘制高亮。

### 9.2 打开、编辑和删除

- 点击橙色高亮打开对应笔记。
- 编辑已有笔记时保留其 `id` 和 `createdAt`。
- 保存成功后更新 `body`、`updatedAt` 和文件修订号。
- 删除前确认；API 保存成功后才移除高亮。
- 有未保存修改时，切换笔记、关闭侧栏、刷新或离开页面都应提醒。
- 右栏无活动编辑器时显示本章笔记列表；点击列表项滚动并打开对应笔记。

### 9.3 锚点恢复顺序

页面加载笔记后逐条恢复：

1. 在 `blockId` 指向的块中，用偏移量截取并与 `exact` 核对。
2. 若不一致，在原块内用 `exact + prefix + suffix` 寻找唯一匹配。
3. 若块已变化，在全章可批注块中用 `exact + prefix + suffix` 寻找唯一匹配。
4. 仍不能唯一定位时，将笔记标记为“需要重新定位”，保留在右栏列表但不绘制高亮。

若恢复到新位置，本次会话可以使用新锚点；只有用户确认保存或编辑该笔记后，才把更新后的锚点写回 JSON，避免页面加载产生无意的仓库变更。

### 9.4 高亮渲染

- 使用语义化 `mark` 元素并附加笔记 ID。
- 同一块内按从后向前的顺序应用多个不重叠范围，避免先插入的元素改变后续偏移。
- 高亮不得破坏 `em`、普通链接等既有行内语义。
- 脚注链接不能成为高亮的一部分。
- 删除或重新渲染高亮后，正文纯文本必须与构建时一致。

## 10. 状态与反馈

界面至少区分以下保存状态：

- 已保存；
- 有未保存修改；
- 正在保存；
- 保存失败；
- 磁盘版本冲突。

所有失败都必须保留用户输入。仅当 API 返回成功时，才显示“已保存”。

脚注加载失败、笔记 JSON 损坏、锚点失配和网络请求失败应显示具体而简短的中文提示，不能只写“发生错误”。

## 11. Safari 与 Chrome 兼容规范

- 不依赖 File System Access API，因为 Safari 不提供同等实现。
- 不依赖实验性 CSS 或仅 Chromium 可用的选择 API。
- 文字选择基于标准 Selection、Range 和 TreeWalker API，并在两种浏览器中实测。
- 避免仅在 `contextmenu` 事件中提供创建笔记入口；浮动按钮是主要入口。
- `position: sticky`、独立滚动容器、抽屉和文本选择应分别在 Safari、Chrome 验证。
- 自动化测试不能替代两种浏览器的人工选择与右键测试。

## 12. 验证与测试

### 12.1 构建测试

- 同一输入连续构建两次，`dist` 无差异。
- 正文有一个 `h1`、八个 `h2`，第五章全部脚注均可解析。
- 输出不存在仓库绝对路径、构建时间或笔记正文。
- 任一正文脚注缺少目标时构建失败。

### 12.2 API 测试

- 正常读取空笔记和已有笔记。
- 新建、修改和删除后生成合法、稳定格式的 JSON。
- 非法章节、路径穿越、错误 schema、过大请求和错误内容类型被拒绝。
- 旧修订号写入返回冲突，原文件不变。
- 模拟写入失败时原 JSON 仍然完整。

### 12.3 浏览器测试

- 三种主题和三栏状态在 Safari、Chrome 中一致。
- 35 条脚注和两个译者注均可开关。
- 单块选择、跨块拒绝、重叠拒绝、保存、编辑和删除符合需求。
- 刷新、重启服务和切换浏览器后，均从同一 JSON 文件恢复笔记。
- 正文前方插入段落并重建后，笔记能回退恢复或明确标为失配。

## 13. Git 与生成物规则

应纳入 Git：

- `Web/src/`、`Web/scripts/`、测试和依赖锁定文件；
- `Notes/Annotations/*.json`；
- Metadata 中的需求、规范和 Roadmap。

不纳入 Git：

- `Web/dist/`；
- Python 缓存、临时写入文件和本地日志；
- 浏览器缓存。

每次提交笔记前，JSON 必须通过 schema 校验。构建或测试不得修改真实笔记文件；API 测试使用临时目录和测试夹具。

## 14. 第一版完成定义

只有同时满足以下条件，第五章原型才算完成：

1. 可从 Markdown 和脚注稳定构建第五章网页。
